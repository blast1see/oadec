## M9 — DAMF and the encoder round trip (first 1:45 of Pi, 126,895 access units)

- `oadec decode --format damf` → `pi-head.atmos{,.metadata,.audio}`:
  5,075,800 frames × 21 channels (conformed 7.1.2 bed + 11 objects), 132
  events from 3,306 payloads.
- Dolby `atmos_info` (DEE 5.2.1) and `atmos_info --validate 1` (DEE 5.7.2):
  both exit 0; the Dolby Atmos Conversion Tool 2.1.2 converts the set to ADM
  BWF with exit 0.
- Events versus truehdd's `pi_p3.atmos.metadata` over the same span: same
  element ids, same event counts per element, identical values; the only
  differences are 21 event times that oadec places 32 samples later —
  the `block_offset_factor` term of the specification, which truehdd ignores.
- DEE `encode_to_atmos_ddp` (768 kbps) accepted the set: MediaInfo reports
  "E-AC-3 JOC / Dolby Digital Plus with Dolby Atmos", complexity index 16,
  15 dynamic objects + LFE bed (`dee/pi-head/pi-head-dee.ec3`).
- DEE `encode_to_dthd` (spatial clusters 16, input type `atmos_mezz`)
  produced a TrueHD Atmos stream that `oadec verify` reports CLEAN; decoding
  it back to DAMF: the LFE bed channel is bit-exact (5,075,800 samples, lag
  0), every object maps 1:1 to one encoded object (normalised correlation
  1.000000) after a permutation, with a uniform gain of −0.00565 dB (ratio
  0.999349, residual max |diff| 99 of 2^23) applied by the encoder's spatial
  coding; metadata events come back with the same values and counts, placed
  earlier by the encoder (one frame boundary before the event).
- In the encoder's E-AC-3 JOC output and in four streaming JOC tracks every
  OAMD update starts on a frame boundary (`oadec emdf`).

## M10 — ADM BWF (first 1:45 of Pi)

- `oadec decode --format adm` → `pi-head.wav`: RIFF/WAVE, JUNK, fmt (PCM
  24 bit, 21 channels), data, axml, chna, dbmd; 128 object blocks.
- `tools/adm_diff.py` against DEE's own `convert_atmos_mezz` output for the
  same DAMF set: **no structural differences** — same chunk order, fmt,
  chna entries, element inventory and ids, every object block's times and
  positions, same dbmd segment layout; only the tool-name strings in dbmd
  differ. Against the Conversion Tool's output: the same, plus a few dbmd
  bytes the newer tool writes differently.
- Round trip through the Conversion Tool (`-f atmos`): the DAMF it produces
  from our ADM reproduces all 132 metadata states and every event time (0
  differences; only the trailing ramp-only events, which ADM cannot carry,
  are gone).
- `bwf_info` (DEE 5.2.1) reads the file (exit 0). The DEE 5.7.2 validator
  and the DEE 5.2.1 `adm` input refuse any ADM file whose dbmd creator string
  is not "Created using Dolby equipment" ("Content was not authored with
  Dolby tools"); with `--dolby-origin-tag` the validator exits 0 and DEE
  encodes the file to E-AC-3 JOC ("Dolby Digital Plus with Dolby Atmos",
  768 kbps, complexity index 16). The DAMF output needs no such marker.
